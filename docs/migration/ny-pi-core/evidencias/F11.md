## Desvios

- D-44: no ruleset da `main` o commit de versão chega por PR, e o check de seções lançadas do upstream falharia em todo
  PR `release/*`. Para esses ramos ele é trocado por um check mais estreito (`scripts/ci/release/`): o diff dos
  `CHANGELOG.md` só pode renomear `## [Unreleased]` para `## [<versão>] - <data>`. O primeiro PR do próximo ciclo
  (#303, ramo `release/next-cycle`) foi recusado por esse check, como desenhado, e refeito como #304; o skill diz para
  não usar `release/*` nesse PR.
- C-F11-04: o `gitleaks dir` sem `-c .gitleaks.toml` acusa as chaves falsas conhecidas dos testes (20 no código-fonte,
  2 no binário). A prova passou a usar a configuração do repositório. A lista de permissões da chave AWS falsa do
  teste do `atualizador` casava só o caminho do repositório; o binário leva a mesma cópia em `nycode/resources/`, e o
  padrão agora casa `(^|/)resources/skills/atualizador/scripts/tests/test_core\.py$`, ainda com a chave exata
  (`condition = "AND"`).
- C-F11-06: `scripts/build-binaries.sh` (arquivo do upstream) não tem `--help` e sai 1; a prova passou a ser
  `bash -n` mais o run do `publish.yml`, que constrói os 6 binários com ele.
- Os binários de `release:local` saem antes do bump e imprimem `1.6.0`; os publicados imprimem `2.0.0`.
