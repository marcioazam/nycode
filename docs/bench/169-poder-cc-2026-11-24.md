# #169: poder estatístico contra o Claude Code (2026-11-24)

Item 8 do [backlog](backlog-nycode-2026-11-24.md). Pergunta: com lotes de ~25 tarefas, braços intercalados e
parada sequencial fixada antes, quantas execuções são precisas para afirmar "o Nycode está à frente do Claude Code"
com poder ≥ 0,80?

## Desenho pré-registrado (antes de qualquer rodada paga)

- Braços: `nycode` (head da `main`) e `cc-vanilla` (Claude Code sem configuração), modelo `claude-sonnet-5-5`,
  intercalados lote a lote na mesma máquina, fila única (`$BENCH_STATE/lock`).
- Afirmação: "à frente" = P(à frente) ≥ 0,80 **e** limite inferior do IC90 pareado por tarefa > 0
  (`bench/stats.py`, a mesma regra do gate).
- Parada: depois de cada lote de ~25 tarefas; para com "à frente" ao cumprir a afirmação, ou com "não mostrado"
  ao esgotar o teto (US$ 80) ou o número de lotes em que a simulação de poder dá ≥ 0,80.
- Regra de futilidade, fixada aqui: se a simulação mostrar que nenhum desenho alcançável dentro do teto chega a
  poder 0,80 para o efeito plausível, nenhuma rodada paga é feita e o item fecha como bloqueado.

## Simulação de poder (custo zero)

Comando (`bench/power/sim.py`, semente fixa, 500 simulações por célula, prior Beta ajustado por tarefa):

```bash
python3 bench/run.py power --ny docs/bench/baseline-main \
  --ref docs/bench/baseline-vanilla-2026-11/sonnet/cc-vanilla \
  --deltas 0,0.03,0.05 --ks 1,3 --ns 25,50,75 --sims 500
python3 bench/run.py power --ny ~/.local/state/bench/k1-hard-2026-11-24 \
  --ref ~/.local/state/bench/hard-2026-11/cc-vanilla --deltas 0,0.05 --ks 3 --ns 12,25 --sims 500
```

## Leitura

- O único desenho com os dois poderes ≥ 0,80 é n = 75, k = 3 (≈ US$ 23) para um Δ real de +4,7 pp. Esse Δ não é
  plausível: o Claude Code acerta 96,1% na base e o Nycode 97,2%, então os dois estão a menos de 4 pp do teto.
- O efeito plausível foi fixado depois de ver os dados (ressalva): Δ observado ≈ +1 pp, não pareado. A conclusão
  não depende dele: nem a +3 pp alguma célula chega a 0,80.
- n = 50 e 75 passam das 42 tarefas observadas: são reamostragens com reposição das taxas encolhidas, não tarefas
  novas.
- Com Δ = 0, P(à frente) ≥ 0,80 sai em 14–17% das rodadas: a afirmação só por P teria falso positivo alto; por
  isso a regra exige também o IC90.
- Custo de cada lote de 25 tarefas k3 nos dois braços: 25 × 3 × (0,029 + 0,073) ≈ US$ 7,7. O desenho 75 × 3 custaria
  ≈ US$ 23 sem poder chegar a uma afirmação; a suíte difícil, 25 × 3 × (0,146 + 0,219) ≈ US$ 27, com poder 0.

## Decisão

**Bloqueado por futilidade, com evidência (regra fixada acima): nenhuma rodada paga feita, US$ 0.** As suítes atuais
estão saturadas para os dois braços (≥ 94%), e, para o efeito plausível (≤ +3 pp), nenhum desenho dentro do teto de US$ 80 tem
poder para afirmar "à frente". A comparação que as suítes conseguem medir é a de custo: US$/acerto do Nycode 0,030 contra 0,076 do
Claude Code na base e 0,155 contra 0,219 na difícil (não pareadas, referência de novembro; ver
[#151](151-velocidade-2026-11-24.md)).

Para destravar, decisão do dono:

1. Construir uma suíte não saturada (alvo: os dois braços entre 40% e 80%), refazer a simulação com ela e só então
   rodar os lotes intercalados.
2. Trocar a afirmação para não inferioridade de acerto mais US$/acerto pareado, decidível com um lote base
   intercalado de 42 tarefas k1 (≈ US$ 4,3).
3. Encerrar o #169 sem afirmação de superioridade de acerto.
